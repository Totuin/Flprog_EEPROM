# Flprog_EEPROM — работа с внутренней и внешней EEPROM

Версия 1.0.1 · Ревизия исходников FLProg · 11.11.2026

## Назначение и основные классы

- `FLProgAbstractEEPROM` — общий интерфейс для RAM-копии данных, чтения и отложенной записи.
- `FLProgInternalEEPROM` — внутренняя EEPROM AVR либо её эмуляция на ESP8266, ESP32, STM32, RP2040.
- `FLProgExternalEEPROM` — внешняя память через I²C-драйвер RT_HW. **Сами драйверы RT_HW не изменены.**

Библиотека резервирует **адрес 0** для байта-маркера инициализации (`initByte`). Пользовательская область: адреса от **1** до **size − 1** включительно. Размер, переданный в конструктор, включает маркер. Если `size <= 1`, места для пользовательских данных нет.

## Порядок использования

1. Создать объект `FLProgInternalEEPROM(size, initByte)` или `FLProgExternalEEPROM(bus, address, size, initByte, type)`.
2. При необходимости вызвать `set*StartValue()` **до** `begin()`. Эти значения используются **только когда байт-маркер в EEPROM отличается** от `initByte`.
3. Один раз вызвать `begin()` в `setup()`.
4. В каждом проходе `loop()` вызывать `pool()`: сохранение изменений происходит **порциями**, а на флеш-эмуляции ещё требуется `commit()` / буферный `flush()`.
5. Для изменения RAM-копии использовать `save*()` с `needUpdate=true` (по умолчанию). `needUpdate=false` не ставит байты в очередь записи. `read*()` читает текущую RAM-копию.

> Важно: `save*()` не гарантирует, что значение уже физически записано. Отключение питания до отработки `pool()` может привести к потере последних изменений. На ESP/RP2040 `pool()` также должен успеть выполнить `commit()`.

## Двоичный формат (совместимость с 1.0.0)

- `Boolean` — отдельный бит заданного байта, от 0 до 7.
- `Byte`/`SignedByte` — 1 байт.
- `Integer`/`UnsignedInteger` — 2 байта, **старший первым**.
- `Long`/`UnsignedLong`/`Float` — 4 байта в исходном машинном порядке; **формат не универсален при переносе EEPROM между MCU с иной архитектурой**.
- Массивы `uint16_t`, `uint32_t` — последовательность двоичных значений в машинном порядке. Параметр `length` означает число **элементов**, а не число байтов.
- `String` — до `length` **байтов** UTF-8/ANSI, свободный хвост заполнен нулём. Ограничение байт может обрезать многобайтный символ.

Два старых имени с опечатками намеренно оставлены для совместимости: `seUnsignedIntegerStartValue()` и `readIUnsignednteger()`.

## I²C, ограничения и износ памяти

- Режим `FLPROG_24C0X_EXTERNAL_EEPROM` использует однобайтовый адрес; библиотека не адресует более 256 байтов и ограничивает `size` этим значением. Реальный объём конкретной микросхемы может быть меньше.
- Режим `FLPROG_24C2X_EXTERNAL_EEPROM` передаёт два адресных байта. Адрес и границы физического чипа должен правильно задавать вызывающий код.
- `pool()` внешней памяти повторяет запись, если RT_HW выставил `codeErr != 0`. При ошибке первичного чтения маркера **не начинается стирание/инициализация**.
- Если во время `begin()` произошла ошибка чтения одного из последующих байтов или первичной записи, после восстановления связи `begin()` требуется вызвать повторно; авто-восстановление состояния чтения не реализовано.
- `begin()` при несовпадении маркера на внешней EEPROM может инициализировать **весь** выбранный диапазон. Смена `initByte` намеренно требует повторной инициализации.
- Для сохранности ресурса EEPROM следует избегать записи одних и тех же значений на каждом шаге программы. Библиотека не меняет RAM-копию, если новое значение равно старому.

## Совместимость и проверка

Публичные методы сохранены. Внутренний буфер теперь инициализируется нулями, корректно освобождается деструктором; копирование объектов запрещено, поскольку они владеют динамической памятью. `keywords.txt` проверен, синтаксических ошибок и повторов нет.

Автономные тесты (без реального оборудования): `tests/standalone/run.sh` для AVR, ESP, RP2040, STM32, дополнительно проверены Clang и ASan/UBSan. Для настоящих Arduino Core и плат необходимо отдельно проверить компиляцию и реальные записи/чтения EEPROM.
